Understanding KMS Encryption

AWS Key Management Service — central, managed cryptography for AWS

Regional Fully Managed Preventive Control

What is KMS?

AWS Key Management Service (KMS) is a managed service that lets you create, control, rotate, and audit the cryptographic keys used to encrypt your data across AWS services (S3, EBS, RDS, Secrets Manager, Lambda env vars, etc.) and your own applications.

Key Idea KMS never gives you the raw key material. You ask KMS to encrypt/decrypt, and it does the cryptographic work behind the scenes using FIPS 140-2 validated hardware security modules (HSMs).

Types of Keys

Key TypeDescriptionRotationCost
AWS OwnedOwned and managed by AWS, used across many accounts. Invisible to you.AWS-managedFree
AWS ManagedCreated automatically by AWS services in your account (e.g. aws/s3, aws/ebs).Auto every 1 yrFree
Customer Managed Key (CMK)You create, configure policies, and control. Most flexible.Optional auto (1 yr)$1/month per key

Symmetric vs Asymmetric

Symmetric (AES-256)

Single key for encrypt & decrypt. Fastest. Default and most common. Key never leaves KMS.

Asymmetric (RSA / ECC)

Public/private key pair. Public key can be downloaded. Used for digital signatures and encrypt-outside-AWS scenarios.

Envelope Encryption (Important Concept)

For large data, KMS uses envelope encryption:

  1. KMS generates a Data Key (DEK) using your CMK.
  2. The plaintext DEK encrypts your large data locally (fast).
  3. The DEK itself is encrypted by the CMK and stored alongside the data.
  4. Plaintext DEK is discarded from memory.

This keeps KMS fast and cheap while still protecting the keys.

CLI Examples

# Encrypt a small string
aws kms encrypt \
  --key-id alias/my-key \
  --plaintext fileb://secret.txt \
  --output text --query CiphertextBlob | base64 -d > secret.enc

# Decrypt
aws kms decrypt \
  --ciphertext-blob fileb://secret.enc \
  --output text --query Plaintext | base64 -d

Key Use Cases

  • Encrypting S3 buckets (SSE-KMS)
  • Encrypting EBS volumes & snapshots
  • Encrypting RDS, DynamoDB, Lambda env vars
  • Backing Secrets Manager & SSM Parameter Store SecureStrings
  • Cross-account / cross-region encrypted backups
Remember KMS keys are regional. To copy an encrypted snapshot to another region, you must re-encrypt with a key in the destination region.

AWS Secrets Manager

Securely store, rotate, and retrieve secrets like DB passwords & API keys

Regional Fully Managed Preventive

What is Secrets Manager?

AWS Secrets Manager is a service that lets you store, manage, and automatically rotate secrets (passwords, DB credentials, API keys, OAuth tokens) without hard-coding them in code or config.

Core Features

  • Encryption at rest using KMS
  • Automatic rotation via Lambda (built-in for RDS, Aurora, Redshift, DocumentDB)
  • Fine-grained IAM access per secret
  • Cross-region replication for disaster recovery
  • Versioning with staging labels (AWSCURRENT, AWSPENDING, AWSPREVIOUS)

Secrets Manager vs SSM Parameter Store

FeatureSecrets ManagerSSM Parameter Store
Cost$0.40 / secret / monthFree (Standard)
Auto RotationYes, built-inNo (must build it)
Cross-region replicationYesNo
Max size64 KB4 KB (Std) / 8 KB (Adv)
Best forProduction credentials, DB passwordsConfig values, feature flags, env settings

CLI Examples

# Store a secret
aws secretsmanager create-secret \
  --name prod/db/password \
  --secret-string '{"username":"admin","password":"S3cure!"}'

# Retrieve a secret
aws secretsmanager get-secret-value \
  --secret-id prod/db/password \
  --query SecretString --output text

Common Use Cases

  • Database credentials for RDS / Aurora with auto-rotation
  • Third-party API keys (Stripe, Twilio, Slack)
  • OAuth tokens / refresh tokens
  • Multi-account secret sharing using resource policies
Best Practice Never hard-code secrets in code or environment variables in plaintext. Reference them by ARN, and load at runtime via the SDK (it caches automatically).

AWS Certificate Manager (ACM)

Free public SSL/TLS certificates with auto-renewal

Regional (most uses) Fully Managed Preventive

What is ACM?

AWS Certificate Manager (ACM) provisions, manages, and deploys public and private SSL/TLS certificates for your AWS resources. Public certs are free, and ACM handles renewal automatically.

Two Types of Certificates

Public Certificates

For internet-facing endpoints. Free. Auto-renewed by AWS as long as DNS validation stays in place.

Private Certificates (ACM PCA)

For internal apps / VPC traffic. Uses a Private CA. Paid service. Useful for mutual TLS (mTLS).

How Validation Works

  1. DNS Validation (recommended): Add a CNAME record to your domain — ACM validates and continues to renew automatically.
  2. Email Validation: ACM emails the domain owner. Manual; not ideal for automation.

Where Can ACM Certs Be Used?

  • ELB / ALB / NLB (regional)
  • CloudFront — must be issued in us-east-1 (N. Virginia) only
  • API Gateway
  • App Runner, Cognito, Elastic Beanstalk
Gotcha For CloudFront distributions, certificates must be in us-east-1. For ALB/NLB, the cert must be in the same region as the load balancer.

Cert Renewal

  • Public certs auto-renew up to 60 days before expiry (DNS validation must remain valid).
  • Imported certs (from outside AWS) are NOT auto-renewed — you must rotate them yourself.

AWS WAF & Shield

Web Application Firewall (Layer 7) + DDoS Protection (Layer 3/4)

Global & Regional Preventive

AWS WAF — Web Application Firewall

WAF protects your web apps from common Layer 7 (HTTP/HTTPS) attacks like SQL injection, cross-site scripting (XSS), bot traffic, and OWASP Top 10 threats. It works on CloudFront, ALB, API Gateway, AppSync, and App Runner.

Key WAF Building Blocks

  • Web ACLs — collections of rules attached to an AWS resource
  • Rules — conditions that allow/block/count/captcha requests
  • Rule Groups — reusable bundles (your own or AWS Managed)
  • AWS Managed Rules — pre-built protections (Common Rule Set, Known Bad Inputs, SQLi, etc.)

Common WAF Use Cases

  • Block requests from specific countries (geo-match)
  • Rate limiting (e.g. block IPs that send > 2000 requests / 5 min)
  • Block SQL injection / XSS payloads
  • CAPTCHA challenges for suspicious bots

AWS Shield — DDoS Protection

Shield protects against DDoS attacks at Layers 3 (network) and 4 (transport).

TierCostWhat You Get
Shield Standard Free (auto-on) Protection against common SYN/UDP floods, reflection attacks for all AWS customers (CloudFront, Route 53, ELB).
Shield Advanced $3,000 / month + data fees Enhanced detection, 24×7 DDoS Response Team (DRT), cost protection (refund for scaling charges during attack), Global Accelerator + EC2 protection, WAF included free.
Layered Defense Shield handles volumetric/network attacks (Layer 3/4). WAF handles application attacks (Layer 7). Use them together on CloudFront/ALB for full coverage.

Amazon GuardDuty

Intelligent threat detection using ML & threat intelligence

Regional Detective Control

What is GuardDuty?

Amazon GuardDuty is a continuous, intelligent threat-detection service that uses machine learning, anomaly detection, and integrated threat intelligence feeds to identify malicious or unauthorized behavior in your AWS account.

Zero Setup Just enable it. No agents, no infrastructure changes. GuardDuty automatically analyzes the data sources below.

Data Sources GuardDuty Analyzes

  • VPC Flow Logs — network traffic patterns
  • CloudTrail Management Events — API activity (logins, IAM changes)
  • CloudTrail S3 Data Events — object-level access
  • DNS Logs — domain lookups (e.g. crypto-mining domains)
  • EKS Audit Logs — Kubernetes API activity
  • Lambda Network Activity
  • RDS Login Events
  • EBS Volume Malware Scanning (add-on)

Example Findings

  • EC2 instance communicating with a known crypto-mining IP
  • Root user logging in from an unusual country
  • IAM credentials leaked on GitHub being used externally
  • Unusual API call pattern (e.g. mass ListBuckets)
  • S3 bucket accessed from a Tor exit node

Severity Levels

  • Low (1.0–3.9): Suspicious but possibly legitimate
  • Medium (4.0–6.9): Investigate soon
  • High (7.0–8.9): Likely real threat — act now

Integrations

  • EventBridge → Slack / PagerDuty / Lambda for auto-remediation
  • AWS Security Hub central dashboard
  • AWS Detective for deeper investigation

Amazon Macie

Sensitive data discovery for S3 (PII, PHI, secrets)

Regional Detective Control

What is Macie?

Amazon Macie is a fully managed data security service that uses machine learning and pattern matching to discover and protect sensitive data stored in Amazon S3.

What Macie Can Detect

  • PII — names, addresses, phone numbers, SSN, passport IDs
  • PHI — medical records (HIPAA)
  • Financial Data — credit card numbers, bank accounts
  • Credentials — AWS access keys, private keys, OAuth tokens accidentally stored in S3
  • Custom data identifiers using regex (e.g. employee IDs)

What Macie Tells You

  • Which S3 buckets contain sensitive data
  • Which buckets are public, unencrypted, or shared with other accounts
  • Bucket inventory + risk score

Two Types of Findings

Policy Findings

Bucket-level issues: public access, no encryption, shared with unknown accounts.

Sensitive Data Findings

Object-level issues: a CSV file contains 10,000 credit card numbers.

Common Use Cases

  • Compliance (GDPR, HIPAA, PCI-DSS) — prove you know where sensitive data lives
  • Detecting accidentally exposed PII
  • Pre-migration audits (before opening up an S3 bucket)
Macie vs GuardDuty Macie = "what's IN my S3 data?" (content-aware).
GuardDuty = "who's BEHAVING strangely in my account?" (activity-aware).

Amazon Inspector

Automated vulnerability scanning for EC2, ECR, & Lambda

Regional Detective Control

What is Inspector?

Amazon Inspector is an automated vulnerability management service that continuously scans AWS workloads for software vulnerabilities (CVEs) and unintended network exposure.

What Inspector Scans

ResourceWhat's Checked
EC2 Instances OS package vulnerabilities (CVEs) + network reachability findings. Uses SSM Agent (no Inspector agent needed in v2).
ECR Container Images Scans images on push and continuously rescans for newly published CVEs.
Lambda Functions Scans function code & layers for vulnerable third-party packages.

How It Works

  1. Enable Inspector in the account/Organization.
  2. Inspector pulls software inventory from SSM, ECR, and Lambda automatically.
  3. It cross-references inventory against CVE feeds (CISA, NVD, vendor advisories).
  4. Findings are scored using a contextualized Inspector risk score (CVSS adjusted by exploitability and reachability).

Sample Findings

  • EC2 instance running OpenSSL with CVE-2023-XXXX
  • ECR image based on outdated Alpine with critical glibc vuln
  • Lambda function using a vulnerable version of log4j
  • EC2 security group exposing port 22 to 0.0.0.0/0

Integrations

  • AWS Security Hub — centralized findings dashboard
  • EventBridge — automated remediation pipelines
  • AWS Organizations — enable across all accounts centrally
Inspector vs GuardDuty vs Macie — Quick Cheat Sheet
  • Inspector — Are my workloads vulnerable? (CVE scanning)
  • GuardDuty — Is someone attacking me right now? (threat detection)
  • Macie — Is sensitive data exposed in S3? (data classification)
