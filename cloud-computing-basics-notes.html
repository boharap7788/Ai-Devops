Basic Overview

What cloud computing is, in plain English

Foundation Beginner-Friendly

What is Cloud Computing?

Cloud Computing is the on-demand delivery of IT resources — servers, storage, databases, networking, software, AI — over the internet, with pay-as-you-go pricing.

Instead of buying physical computers and running them in your office, you rent computing resources from a cloud provider (AWS, Azure, GCP) and only pay for what you use.

Simple Analogy

Cloud is like electricity. You don't build your own power plant at home — you plug into the wall and pay only for the units you consume. Cloud computing works the same way for IT resources.

Why Cloud?

  • No hardware to buy — start in minutes, not months
  • Elastic — scale up during traffic spikes, scale down at night
  • Pay only for usage — per second / per request
  • Global reach — deploy in any country in clicks
  • Reliability — managed, replicated, backed up by the provider

Top Cloud Providers

AWS

Amazon Web Services — market leader, ~200+ services.

Microsoft Azure

Strong in enterprise & hybrid cloud.

Google Cloud (GCP)

Strong in data, ML, and Kubernetes.

Understanding Servers & Cloud Benefits

From physical machines in a data center to the cloud

Foundation Concept

What is a Server?

A server is just a powerful computer that serves requests from other computers (clients). When you open a website, your browser (client) talks to a web server somewhere on the internet.

Types of Servers

  • Web Server — serves websites (Nginx, Apache)
  • Application Server — runs business logic (Tomcat, Node.js)
  • Database Server — stores data (MySQL, PostgreSQL)
  • File Server — stores and shares files
  • Mail Server — sends & receives email

The Old Way — On-Premise (On-Prem)

Before the cloud, companies bought their own servers and kept them in a server room or rented a data center.

Problems with On-Prem

  • High upfront cost (CapEx) — hardware, racks, cooling, electricity
  • Slow procurement — weeks/months to add a new server
  • Capacity guessing — over-provision (wasted $$) or under-provision (downtime)
  • You manage everything — security, patching, backups, replacement
  • Hard to scale globally

Benefits of the Cloud

BenefitWhat It Means
No CapExTrade huge upfront purchases for variable, pay-as-you-go expenses (OpEx).
ElasticityScale up & down automatically based on demand.
Speed & AgilityProvision a server in seconds, not weeks.
Global ReachDeploy in any region of the world in minutes.
Reliability / HAMulti-AZ & multi-region replication is built-in.
SecurityProvider handles physical security, you focus on app/data.
Focus on BusinessStop maintaining hardware, build features instead.
Remember CapEx → OpEx is one of the biggest financial wins of moving to cloud.

Different Types of Cloud (Deployment Models)

Public · Private · Hybrid · Multi-Cloud

Deployment Models

The 4 Cloud Deployment Models

1. Public Cloud

Resources owned by a third-party provider (AWS, Azure, GCP) and shared with many tenants. Pay-as-you-go. Most common.

2. Private Cloud

Cloud built for and used by a single organization. Hosted on-prem or by a dedicated provider. Maximum control & compliance.

3. Hybrid Cloud

Mix of public + private (or on-prem). E.g. sensitive data stays on-prem, web app runs on AWS.

4. Multi-Cloud

Using multiple public providers (AWS + Azure + GCP) to avoid vendor lock-in or use best-of-breed services.

Comparison Table

ModelCostControlScalabilityBest For
PublicLowestLowHighestStartups, web apps, most workloads
PrivateHighestHighestLimitedBanks, defence, strict compliance
HybridMediumMediumHighEnterprises during cloud migration
Multi-CloudVariableMediumHighLarge companies avoiding lock-in
Real World Most large enterprises today run a hybrid + multi-cloud setup — keeping some legacy apps on-prem while using AWS for new workloads and Azure for Microsoft 365 integration.

Cloud Computing Model (Service Models)

IaaS · PaaS · SaaS — who manages what?

Service Models

The 3 Cloud Service Models

IaaS

Infrastructure as a Service — you rent raw compute, storage, network. You manage OS & everything above.

PaaS

Platform as a Service — you bring your code, the platform runs it. No server management.

SaaS

Software as a Service — fully ready software you just log in and use.

Who Manages What?

Layer On-Prem IaaS PaaS SaaS
ApplicationYouYouYouProvider
DataYouYouYouProvider
RuntimeYouYouProviderProvider
MiddlewareYouYouProviderProvider
Operating SystemYouYouProviderProvider
VirtualizationYouProviderProviderProvider
Servers / Storage / NetworkYouProviderProviderProvider

AWS Examples for Each Model

  • IaaS: EC2, EBS, VPC
  • PaaS: Elastic Beanstalk, AWS App Runner, RDS, Lambda
  • SaaS: Amazon WorkMail, Amazon Chime, Amazon Connect

Pizza Analogy

On-Prem = make pizza at home (buy oven, dough, cheese, everything).
IaaS = take-home pizza kit (provider gives ingredients, you cook).
PaaS = pizza delivery (you provide the dining table, provider cooks).
SaaS = dining at a restaurant (you just eat).

AWS Infrastructure

Regions, Availability Zones, Edge Locations & more

AWS Architecture

The AWS Global Infrastructure Hierarchy

AWS Global Network
│
├── Region (e.g. us-east-1, ap-south-1)
│    ├── Availability Zone (AZ) — at least 3 per region
│    │     └── Data Center(s) — physical buildings
│    └── Local Zones (optional, for low-latency in cities)
│
├── Edge Locations (400+) — for CloudFront / Route 53
└── Wavelength Zones — at telecom 5G edge

Regions

  • A Region is a physical geographic area (e.g. ap-south-1 = Mumbai).
  • AWS has 30+ regions worldwide.
  • Each region is fully independent — data does not leave the region unless you copy it.
  • Choose a region based on: latency, compliance, service availability, cost.

Availability Zones (AZs)

  • Each region has 3 or more AZs (e.g. us-east-1a, 1b, 1c).
  • An AZ is one or more physical data centers with independent power, cooling, networking.
  • AZs are kilometers apart but connected by ultra-low-latency fiber.
  • Designed to be isolated from failures in other AZs.
Best Practice Always deploy critical workloads across at least 2 AZs for high availability. If one AZ fails, your app keeps running in the other.

Edge Locations

  • Hundreds of small data centers spread across the world (in cities, ISPs).
  • Used by CloudFront (CDN), Route 53 (DNS), Global Accelerator.
  • Bring content physically closer to end-users for low latency.

Other Specialty Locations

  • Local Zones — extension of a region close to large population centers (e.g. Los Angeles)
  • Wavelength Zones — embedded in 5G telecom networks
  • AWS Outposts — AWS hardware running in your own data center
  • GovCloud — special regions for U.S. government workloads

Understanding Hypervisor

The technology that makes the cloud possible

Virtualization

What is a Hypervisor?

A hypervisor (also called Virtual Machine Monitor / VMM) is a software layer that lets one physical computer run multiple virtual machines (VMs) at the same time, each thinking it has its own CPU, RAM, and disk.

Simple Analogy

Think of a physical server as an apartment building, and the hypervisor as the building manager. The manager divides the building into separate flats (VMs), each with its own door, kitchen, water meter — but they all share the same physical structure underneath.

Two Types of Hypervisors

Type 1 — Bare Metal

Runs directly on the hardware. No host OS. Faster, more secure. Used in data centers / cloud.
Examples: Xen, KVM, VMware ESXi, Microsoft Hyper-V, AWS Nitro.

Type 2 — Hosted

Runs on top of a host OS (Windows/macOS/Linux). Easier to install. Slower. Used on developer laptops.
Examples: VirtualBox, VMware Workstation, Parallels.

Hypervisor vs Container

Virtual Machine (Hypervisor)Container (Docker)
What's virtualizedWhole hardwareOS / processes
Includes own OS?YesNo (shares host kernel)
Boot timeMinutesSeconds
SizeGBsMBs
IsolationStrongProcess-level

How AWS Uses Hypervisors

  • Older EC2 instances ran on a customized Xen hypervisor.
  • Modern EC2 instances run on the AWS Nitro System — a lightweight, hardware-accelerated hypervisor that delivers near bare-metal performance.
  • This is why one physical server in an AWS data center can host many EC2 instances belonging to different customers — securely.

Global vs Regional Service

Where does an AWS service actually live?

AWS Scope

Every AWS service has a scope — it either belongs to a single region or runs globally.

Global Services

Created once and visible the same way from anywhere in the world. No region selector at top of console.

  • IAM — users, groups, roles, policies
  • Route 53 — DNS
  • CloudFront — CDN
  • AWS Organizations
  • WAF (when used with CloudFront)
  • AWS Shield
  • Billing & AWS Support

Regional Services

Tied to a specific region. Resources created in ap-south-1 won't appear in us-east-1.

  • EC2, EBS, VPC, Subnets
  • RDS, DynamoDB (data is regional, can be globally replicated)
  • S3 — bucket is regional but namespace is global
  • Lambda, ECS/EKS, API Gateway
  • KMS, Secrets Manager, ACM (mostly)
  • CloudWatch Logs, SNS, SQS

Service Scope Cheat Sheet

ScopeExamplesNote
GlobalIAM, Route 53, CloudFront, Organizations, ShieldOne copy across all regions
RegionalEC2, RDS, Lambda, VPC, KMSResources isolated per region
ZonalEBS volumes, EC2 instance, NAT GatewayLives in a specific Availability Zone
Hybrid scopeS3 (regional bucket, global namespace), DynamoDB Global TablesSpecial replication features
Watch Out If you create resources in the wrong region, you may "lose" them in the console (you just need to change region). Also, cross-region traffic and replication usually cost extra.

One-Page Summary

Quick revision before exam / interview

  • Cloud Computing = on-demand IT over the internet, pay-as-you-go.
  • Servers are just powerful computers; cloud lets you rent them by the second.
  • 4 Cloud Types: Public, Private, Hybrid, Multi-Cloud.
  • 3 Service Models: IaaS (raw infra), PaaS (platform), SaaS (software).
  • AWS Infra: Region → AZ → Data Center, plus Edge Locations for CDN/DNS.
  • Hypervisor = software that runs many VMs on one machine; AWS uses Nitro.
  • HA & Fault Tolerance need multi-AZ; DR often needs multi-region.
  • Global services: IAM, Route 53, CloudFront, Shield. Most others are regional.
